Model math

Predictor math.

The firmware does not use one giant closed-form apogee equation. It builds a current coast state, computes air-relative aerodynamic forces, turns those forces into accelerations and pitch dynamics, then numerically rolls the state forward until vertical velocity reaches zero.

Ballistic baseline

Sanity check

The simplest no-drag coast estimate is useful as a bound and a debugging reference. If the rocket is at altitude \(h\) and climbing vertically at \(v_z\), gravity alone adds \(\frac{v_z^2}{2g}\) meters before apogee.

No-drag height remaining

\(h_{\mathrm{apogee}} = h + \frac{v_z^2}{2g}\)

This is intentionally high when drag matters. The firmware uses the same idea as a conservative telemetry bound when integration hits a step limit, but marks the prediction uncertain for control.

Time remaining

\(t_{\mathrm{apogee}} = \frac{v_z}{g}\)

This only holds for pure gravity. With drag, effective deceleration is larger and time-to-apogee is shorter.

Aero force model

CFD to acceleration

Air-relative speed

\(\vec{v}_{\mathrm{air}} = \vec{v}_{\mathrm{vehicle}} - \vec{v}_{\mathrm{wind}}\)

Wind has to be removed before Mach and AoA are computed. A tailwind or headwind changes the force even if ground-relative velocity looks the same.

Mach number

\(M = \frac{|\vec{v}_{\mathrm{air}}|}{a(T)}\)

The speed of sound depends on temperature, so the environment model matters. Mach chooses which CFD slices are blended.

Density scaling

\(F_{\mathrm{scaled}} = F_{\mathrm{CFD}} \frac{\rho(h)}{\rho_{\mathrm{ref}}}\)

The table stores forces at a reference density. The predictor scales forces down as altitude rises and air gets thinner.

Newton's law

\(\vec{a} = \frac{\vec{F}}{m}\)

Axial and normal force become vertical and horizontal acceleration after projection through the current zenith angle.

State integration

RK4

Drag changes quickly during coast because speed, Mach, angle of attack, and flap position are all changing. The predictor uses RK4 on the trusted path because it samples the derivative at the beginning, two midpoints, and the end of each step.

State vector

\(x = [h,\ v_z,\ v_x,\ \theta,\ \omega,\ \delta]\)

Altitude, vertical velocity, horizontal speed, zenith, angular rate, and physical flap angle are propagated together.

RK4 update

\(x_{n+1} = x_n + \frac{\Delta t}{6}(k_1 + 2k_2 + 2k_3 + k_4)\)

Each \(k_i\) is a derivative sample from the aero/gravity/pitch model at a different point inside the timestep.

When the final step crosses from climbing to descending, the code refines inside that bracket. That avoids reporting the first descending sample as apogee, which would bias the result low.

Where it lives

Source map
  • apogee_model.hDefines the state, force interpolation, RK4 rollout, zero-crossing refinement, drag sensitivity bounds, and adaptive Mach drag scale.
  • flight_computer.cppBuilds the predictor seed from the estimator, clamps suspect inputs, computes confidence flags, and updates adaptive drag only in clean coast.
  • cfd_table.cppLoads the CFD grid and refuses incomplete/non-finite force cells so interpolation cannot silently ingest missing data.
  • math_utils.hContains quaternion normalization, slerp, zenith extraction, and exponential-map gyro integration used by the attitude path.
